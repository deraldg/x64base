  in the tree can reach it: every SQLSEL line in the tree carries a FROM, is a

  failed for exactly this reason and the guard it was meant to prove was held
  back rather than committed unproven. This transcript is that debt paid.

TRANSCRIPT
----------
. SQLSEL LNAME = "SMITH"
SQLSEL: that is not a statement, and the legacy predicate form has been retired.
  SQLSEL is the statement verb: SQLSEL <list> FROM <table> [WHERE ...].
  For a predicate scan over the current work area use COUNT, which carries
  the listing and verbose forms: COUNT FOR <expr>, COUNT LIST, COUNT VERBOSE.
  COUNT honours SET FILTER and SET DELETED as the logical rowset; this form
  did not, which is why it is gone.
. QUIT

READING
  The text matches `src/cli/cmd_sql_select.cpp`'s dispatch tail verbatim,
  five lines, no leading scan and no row count -- so control reached the tail
  rather than any surviving legacy path. `LNAME = "SMITH"` is the exact shape
  the retired form accepted: a bare predicate with no FROM. Before this change
  it would have been parsed as a predicate and scanned against the current
  work area using the file's own private DelMode and raw walk, with no regard
  for SET FILTER or SET DELETED.
