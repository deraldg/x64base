Laboratory Campus

An alpha collaboration campus for planning, in-development labs, and existing x64base/DotTalk++ learning evidence.

Overview

The Laboratory Campus is the learning and collaboration layer for x64base and DotTalk++. LabTalk remains the project mark and legacy name; Laboratory Campus is the public-facing name.

Academic Start Here

Educators and researchers can use the Academic Start Here pathway to review the research agenda, a guided exemplar lesson, runtime evidence, research safeguards, and current collaboration needs without first traversing the full technical documentation set.

Cases and Storyboard

The Cases and Storyboard page is the visible entry point for the LabTalk / DotTalk++ systems storyboard deck, database-history case families, source-memory stories, and proof-aware classroom paths. It connects personal experience, historical data systems, live runtime evidence, and lessons.

It presents the system as a set of laboratories:

  • runtime systems
  • historical data systems from punch cards to cloud computing and AI
  • self-documenting systems
  • datasets and cases
  • GUI, pycrud, and portal experiments
  • proof-backed lessons

What It Is

The Laboratory Campus is a way to organize learning around live systems:

concept -> app -> dataset -> command -> proof -> case -> lesson

That pattern lets a learner see not only what a database command does, but where the explanation came from, what data was used, what proof exists, and how the idea fits into computing history.

The Database Evolution Path integrates the Laboratory Campus / DotTalk++ storyboard deck as a public teaching path and local source artifact.

The Education Features page connects the campus to source-defined teaching mechanisms: timed IDX sort/index labs, student command and function extension hooks, pre/post polling hooks, and source-derived command/function catalogs.

The Lesson Platform curates student lesson seeds, career lessons learned while building the system, and structured lesson suggestions from educators, students, technical writers, and collaborators.

The local LabTalk portal also exposes pycrud as a launcher-backed campus tool. pycrud is a small Python/Tk CRUD and relational teaching surface with a local FastAPI bridge (pydottalk_api) for schema, fixtures, header metadata, and table readback. It belongs in LabTalk as a practical GUI/database literacy lab, not as the DotTalk++ engine itself. The native pydottalk engine binding, the prototype API bridge, and the teaching app are documented separately in Python Integration.

AI Portal — Alpha/Experimental

The AI Portal is the proposed AI-facing campus entrance. It aims to prepare an AI for a series of tasks through curated, typed jumps, authority and proof checks, bounded context packets, and guarded action planning.

The lane is Alpha/Experimental. Current onboarding documents, registries, launcher surfaces, and MAINT AI readback are seeds—not production autonomous memory and not a replacement for runtime truth or human authorization.

Current Position

The Laboratory Campus is alpha: a hybrid of planning material, implemented pieces, and in-development collaboration areas. It is an educational campus direction and collaboration frame, not yet a finished packaged distribution.
