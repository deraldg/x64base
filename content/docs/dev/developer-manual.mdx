## What's inside

The manual is assembled from a declared bill of materials — a spine of harvested
reference, an authored narrative branch, generated front/back matter, and bound
diagrams:

| Section | Contents |
| --- | --- |
| Front matter | Title, provenance & attestation, table of contents |
| Spine | Command reference (191 pages), function reference (73 core functions plus 2 extensions), SET family, error/message catalog |
| Chapters | Tables & the data model, RAM DBF/VDISK, identity/authentication/RBAC, runtime definition and HELP controls, command dispatch, expressions, indexing, messages, HELP/metadata alignment, runtime evidence |
| Diagrams | 12 promoted diagrams bound from the attachment matrix |
| Back matter | AI Portal appendix, glossary, index, and a colophon that records how the manual assembled itself |

The currently linked local-preview assembly contains 26 parts, 14,542 lines, 1,666
headings, and all 191 current command pages. Its HTML, Markdown, and 298-page
Letter PDF are bound together by the build manifest; the website staging gate
rejects a missing or stale companion format.

## Status and honesty

The linked manual is an **assembled-candidate** -- guarded by the drift gate but
distinct from the gated, reviewed
[accepted developer manual](/downloads) (the `manual-reviewed` baseline promoted
from public source). Where the two differ, the accepted snapshot is the reviewed
authority; the assembled build is a working copy, not an automatic publication.

Full-stack run `DOCFLUSH-20260825-001` accepted a newer manual candidate as
review-needed (`MANRUN-20260826T012054Z-B9F8B8BD`) without replacing these files.
The owner has ruled that the developer, student, and user manual estate is treated
collectively until a separate hardening pass chooses the durable reader model.
The website therefore links to the manual estate; it does not claim the v6
candidate is already the public reader.

For how the manual is built and kept honest, see
[How the Manual Assembles Itself](/docs/dev/manual-assembly).
