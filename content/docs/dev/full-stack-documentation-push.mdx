## Why this vertical exists

The documentation system derives from source behavior, source comments, usage
contracts, and file metadata. A major messaging and runtime change therefore requires
a governed reharvest: not because every small change deserves a full publication run,
but because this change crossed enough source, HELP, manual, and public-documentation
boundaries to justify the complete vertical.

The chain is:

```text
source and *ref.hpp contracts
-> COMMENTS SRC* evidence and mutation audit
-> CMDHELP build + CMDHELPCHK + locale canaries
-> SelfDoc / reference identity / lineage
-> manualgen candidate + accepted-layer preservation
-> assembled Markdown, HTML, and PDF
-> reviewed website pages and machine-readable feeds
-> human review
-> explicit commit, publication, and live-readback gates
```

## Date and maintenance contract

This page, Current Tasks & Projects, Documentation Progress, project truth, roadmap,
manual landing, and AI Agent Sync are permanent but not static. They use the
`maintained_current` class:

1. Display a reconciled `as_of_date`.
2. Name the authority that feeds the present state.
3. Show proof state and next gate.
4. Replace the present-state region when work advances.
5. Preserve historical event dates and immutable closeout evidence.

Reported products such as benchmark rows and sealed publication checkpoints remain
append-only. Static brand/history pages change only by deliberate human review.

## Additional maintained steps (added in pass 4)

Pass 4 added standing steps to the vertical; **Document FullStack push v5** runs them
by default:

1. **Website matrix gate.** Read and classify against the
   [Website Documentation Matrix](/docs/dev/website-documentation-matrix) at the start
   of the website phase; update and re-audit it at closeout. A stale matrix is a
   fail-closed condition on the website signoff.
2. **Conceptual diagram collection.** The BBS/AI process diagrams and the
   start-to-finish documentation-push DFD are maintained from source `.mmd`;
   regenerate the SVGs from source and never hand-edit a rendered SVG.
3. **AutoSSL trigger.** When the certificate validates, flip the artifact/manual-room
   links to HTTPS and drop the "while SSL is settling" caveats.
4. **Count reconciliation (AIF-032).** Reconcile the command count in source and
   regenerate the data-carrying harvest diagram and command catalog; do not hand-type
   harvest-derived numbers.
5. **Interchange coverage.** New import/export surfaces (such as `AUTODBF`, CSV-to-DBF)
   land in the DotScript CSV/DBF import-export section with a proof label.
