WHAT WAS REMOVED
----------------

    CMD_LOAD,LOAD,command,public,cmd_LOAD,T

LOAD is not a command. It is a SUBCOMMAND, and the row was fabricated.

Evidence, all four checks failing:

  1. HANDLER claims `cmd_LOAD`. No such function exists anywhere in tracked
     source. Verified by reading every tracked .cpp/.hpp/.h/.cc/.cxx/.hxx under
     src, include and bindings into one text blob and testing membership of the
     identifier -- of all 216 HANDLER values in this file, `cmd_LOAD` was the
     ONLY one that did not resolve.
  2. There is no src/cli/cmd_load.* translation unit.
  3. include/dotref.hpp does not list LOAD.
  4. The live canonical table (dottalkpp/data/metadata/SYSCMD.dbf, 203 records)
     does not contain it.

LOAD appears in the codebase only as a subcommand token --
    BETA LOAD, CODASYL LOAD, ERSATZ LOAD, REL LOAD, USER LOAD
-- and in include/reserved_words.hpp. A seed generator promoted that token to a
top-level command and synthesised a plausible handler name to go with it. The
error propagated into BOTH SYSCMD_IMPORT_v1.csv and SYSCMD_IMPORT_v2.csv.

The live table was correct all along. The CSVs were wrong.

The row was removed surgically -- byte replacement of that one CRLF-terminated
line -- so ordering, quoting, CRLF endings and the trailing newline are all
unchanged. Verified 10,480 -> 10,439 bytes, delta exactly 41, and a whitespace-
normalised diff showing that single line and nothing else.

v1 is not edited here. It is refreshed FROM the live table by
tools/fullstack_docs/export_syscmd_mirror.ps1, which drops LOAD as an
acknowledged CSV-only phantom (-AcceptCsvOnly LOAD).


HOW IT WAS FOUND
----------------

Not by review. By exporting the live table to refresh v1 and letting a guard
compare the two. The guard was written to catch the EXPORT dropping table rows
-- which it structurally cannot do, since the row count is checked against the
DBF header -- and instead caught the tracked CSV asserting a command that was
never real. Right alarm, wrong reason, useful result.

Companion finding to AIF-065: nothing in the toolchain was checking whether a
declared thing actually exists downstream.

produced the LOAD row. Each candidate needs adjudication against the command
registry before it is appended to the table, ONE AT A TIME, additively.
