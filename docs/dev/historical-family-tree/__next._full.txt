<h2 id="preserved-archive-hierarchy"><a class="no-underline" href="#preserved-archive-hierarchy">Preserved archive hierarchy</a></h2>
<p>The original SHA-256-bound <code>xbase.zip</code> archive contains three sibling source
branches. DotTalk is physically contained in xBase2:</p>
<pre><code class="language-text">xBase source family
├── xbase/                         core C source, 1993
│   ├── XBASE                     DBF and work-area core
│   ├── XBCMDS                    command and relation layer
│   └── XBINDEX                   index layer
├── xdll/                          DLL-export branch, 1993–1996
│   ├── XBASE                     exported DBF operations
│   ├── XBCMDS                    LibMain, WEP, commands and relations
│   └── XBINDEX                   exported index layer
└── xbase2/                        extended branch, 1995
    ├── DOTTALK.C / DOTTALK.H     DotTalk command shell
    ├── XBASE
    ├── XBCMDS
    ├── XBINDEX
    └── TEST.C
</code></pre>
<p><a href="/docs/dev/historical-source-files">Inspect all 21 preserved files</a>.</p>
<h2 id="later-preservation-and-recovery"><a class="no-underline" href="#later-preservation-and-recovery">Later preservation and recovery</a></h2>
<p>These are later recovery/build lanes. Similar vocabulary and files are
source-evidenced, but this page does not assert an unbroken version-control
chain from the 1995 archive.</p>
<pre><code class="language-text">DotTalk/xBase recovery evidence
├── xBase2 no-touch MSVC bring-up
│   ├── xbase2_legacy.lib
│   └── dottalk_1995.exe
├── gTalk / DotTalk recovery
│   └── buildable sequential shell; index copy stubbed
└── DotTalk old-code recovery
    └── smaller buildable shell; index copy stubbed
</code></pre>
<h2 id="modern-conceptual-continuation"><a class="no-underline" href="#modern-conceptual-continuation">Modern conceptual continuation</a></h2>
<p>The current system carries the engine/shell separation forward, but current
behavior is proved by modern source and runtime evidence—not by the archive:</p>
<pre><code class="language-text">x64base / DotTalk++ composition
├── x64base engine
│   ├── xbase.lib                 physical DBF and record behavior
│   ├── memo.lib                  memo storage behavior
│   └── xindex.lib                optional index provider
└── DotTalk++ runtime
    ├── dottalkpp.exe             command-language host
    └── pydottalk                 Python 3.12 extension surface
</code></pre>
<h2 id="xbase-dll-evidence-boundary"><a class="no-underline" href="#xbase-dll-evidence-boundary">“xBase DLL” evidence boundary</a></h2>
<p>The remembered “xBase DLL” name maps to the preserved <code>xdll/</code> branch. The
source contains <code>LibMain</code>, <code>WEP</code>, and many <code>FAR PASCAL _export</code> declarations,
which proves DLL-oriented source. No historical binary named <code>xbase.dll</code> was
located in the reviewed archive or recovery roots. The portability record
builds <code>xdll.lib</code>.</p>
<p>That distinction is intentional:</p>
<ul>
<li><strong>preserved:</strong> the branch name, source files, exports, dates, and hashes;</li>
<li><strong>not claimed:</strong> possession or runtime verification of an original
<code>xbase.dll</code> binary.</li>
</ul>
