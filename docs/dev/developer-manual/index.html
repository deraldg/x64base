Developer Manual (Assembled)

Read the latest assembled DotTalk++ / x64base developer manual online, or download it as PDF or Markdown. Always-current permalinks, regenerated from source by the manifest-driven assembler and guarded by a drift gate.

This is the reader entry for the assembled developer manual — the whole thing, built from source by the manifest-driven assembler and kept current by a drift gate. The links below are permalinks: every rebuild overwrites the same files, so they always resolve to the newest build.

  • PDF — print-ready.
  • Markdown — the source form.
  • Build manifest — exact source commit, part counts, and checksums for this build.

What's inside

The manual is assembled from a declared bill of materials — a spine of harvested reference, an authored narrative branch, generated front/back matter, and bound diagrams:

SectionContents
Front matterTitle, provenance & attestation, table of contents
SpineCommand reference (191 pages), function reference (74 functions), SET family, error/message catalog
ChaptersTables & the data model, RAM DBF/VDISK, identity/authentication/RBAC, runtime definition and HELP controls, command dispatch, expressions, indexing, messages, HELP/metadata alignment, runtime evidence
Diagrams12 promoted diagrams bound from the attachment matrix
Back matterAI Portal appendix, glossary, index, and a colophon that records how the manual assembled itself

The current local-preview assembly contains 26 parts, 14,542 lines, 1,666 headings, and all 191 current command pages. Its HTML, Markdown, and 298-page Letter PDF are bound together by the build manifest; the website staging gate rejects a missing or stale companion format.

Status and honesty

The assembled manual is an assembled-candidate — regenerated from source on each build and guarded by the drift gate, but distinct from the gated, reviewed accepted developer manual (the manual-reviewed baseline promoted from public source). Where the two differ, the accepted snapshot is the reviewed authority; the assembled build is the always-current working copy.

For how the manual is built and kept honest, see How the Manual Assembles Itself.
