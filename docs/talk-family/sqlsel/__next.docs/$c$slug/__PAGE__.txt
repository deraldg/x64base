6:Te20,<h2 id="what-it-does"><a class="no-underline" href="#what-it-does">What it does</a></h2>
<p>SQLsel names the SQL-facing query workflows in DotTalk++ / x64base.</p>
<p>Its subject is set-oriented retrieval rather than cursor navigation. It covers:</p>
<ul>
<li>a <code>SELECT</code> statement over an open work area</li>
<li><code>WHERE</code> filtering, <code>ORDER BY</code> with direction, <code>LIMIT</code></li>
<li><code>COUNT(*)</code> with or without a predicate</li>
<li>statement scoping: no session state read, no cursor moved</li>
</ul>
<p>Real local command surfaces include:</p>
<pre><code class="language-text">SQLSEL SELECT SID,LNAME FROM STUDENTS
SQLSEL SELECT * FROM STUDENTS WHERE MAJOR = "CSCI"
SQLSEL SELECT SID,LNAME FROM STUDENTS ORDER BY LNAME DESC LIMIT 2
SQLSEL SELECT COUNT(*) FROM STUDENTS WHERE GPA >= 3.0
SQLSEL USAGE
</code></pre>
<h2 id="statement-scoping"><a class="no-underline" href="#statement-scoping">Statement scoping</a></h2>
<p>A SQLsel statement names its own table and does not consult session state. It
ignores any active <code>SET FILTER</code>, does not depend on the current work area, and
restores every cursor it moves. Two consequences worth knowing:</p>
<ul>
<li>the same statement returns the same rows regardless of where you were
positioned or what filter was set</li>
<li>it reads <strong>committed</strong> table truth, so under <code>TABLE BUFFER ON</code> an uncommitted
edit is not visible to it</li>
</ul>
<p>The second is a deliberate ruling rather than an accident. A statement that
filtered on committed data but displayed buffered data would return a row that
visibly fails its own <code>WHERE</code> clause.</p>
<h2 id="verification"><a class="no-underline" href="#verification">Verification</a></h2>
<p><code>REGRESSION SQLSEL_SELECT_V1</code> compares every result set against an in-process
SQLite oracle over identical data in the same run, and asserts:</p>
<ul>
<li><code>ORDER BY</code> sorts the full match set before <code>LIMIT</code> cuts it</li>
<li>cursor position is unchanged, checked by data</li>
<li>corrective errors for an unopened table, an expression where a column belongs,
a bad <code>LIMIT</code>, an unknown <code>ORDER BY</code> field, and <code>ORDER BY</code> on <code>COUNT(*)</code></li>
<li><code>LIMIT</code> reports what it withheld; <code>ORDER BY</code> reports its access path</li>
</ul>
<h2 id="not-yet-implemented"><a class="no-underline" href="#not-yet-implemented">Not yet implemented</a></h2>
<p><code>JOIN</code>, <code>GROUP BY</code> / <code>HAVING</code>, expression projection, SQL DML, and the bare
<code>SELECT</code> alias. The table must already be open: SQLsel reads open work areas and
does not open files.</p>
