1d:T176f,<h2 id="status-and-authority"><a class="no-underline" href="#status-and-authority">Status and authority</a></h2>
<p>This is an <strong>Alpha/Experimental public projection</strong> of the AI Portal schema and
identifier model. It gives outside AI partners a stable, readable snapshot. It
does not replace the implementation, runtime evidence, HELP and metadata
stores, accepted manuals, or owner rulings that support it.</p>
<h2 id="registered-dbf-schemas"><a class="no-underline" href="#registered-dbf-schemas">Registered DBF schemas</a></h2>









































<table><thead><tr><th>Domain</th><th>Tables</th><th>Upstream definition</th><th>Portal posture</th></tr></thead><tbody><tr><td>Identity and RBAC</td><td><code>SYSUSER</code>, <code>SYSMEMBER</code>, <code>SYSROLE</code>, <code>SYSPERM</code>, <code>SYSROLEPERM</code>, <code>SYSMEMROLE</code>, <code>SYSOVERRIDE</code>, <code>SYSASSIGN</code>, <code>SYSGRANT</code></td><td>identity schema</td><td>Governed per-table CRUD and close policies</td></tr><tr><td>AI-BBS and Pseudo-Chat</td><td><code>SYSBOARD</code>, <code>SYSTHREAD</code>, <code>SYSPOST</code></td><td>BBS schema</td><td>Generic Portal CRUD is read-only; the BBS daemon owns writes</td></tr><tr><td>Global rulings</td><td><code>SYSRULING</code></td><td>ruling schema</td><td>Append-only doctrine and owner decisions</td></tr><tr><td>Portal tracking</td><td><code>SYSLANE</code>, <code>SYSRUN</code>, <code>SYSRUNLANE</code>, <code>SYSPROOF</code>, <code>SYSTASK</code></td><td>tracking schema</td><td>Governed tracking; run history is append-only</td></tr><tr><td>SelfDoc command catalog</td><td><code>SYSCMD</code></td><td>reviewed SelfDoc catalog schema</td><td>Read-only metadata projection</td></tr></tbody></table>
<p>The registered surface contains 19 table schemas across five custody domains.
Registration does not assert that every table is seeded or current. Mutation
policy follows each table's owner; the word "database" is not a permission
model.</p>
<h2 id="identity-crosswalk"><a class="no-underline" href="#identity-crosswalk">Identity crosswalk</a></h2>























































<table><thead><tr><th>Identity</th><th>Role</th><th>Primary relationship</th></tr></thead><tbody><tr><td><code>project.&#x3C;domain>.&#x3C;name></code></td><td>Durable program</td><td>Parent of governed lanes</td></tr><tr><td><code>AIF-NNN</code></td><td>Intake or work lane</td><td>Links project, lifecycle, work, proof, and closeout</td></tr><tr><td><code>PDLC</code> / <code>SDLC</code></td><td>Process classification</td><td>PDLC may nest inside SDLC; neither allocates identities</td></tr><tr><td><code>M&#x3C;n></code> or named gate</td><td>Evidence checkpoint</td><td>Belongs to one lane</td></tr><tr><td><code>R&#x3C;n></code></td><td>Doctrine or owner ruling</td><td>One global sequence shared by every lane</td></tr><tr><td>provider/date run id</td><td>Bounded execution</td><td>Links acting member, project, and one or more lanes</td></tr><tr><td><code>task.*</code></td><td>Work item</td><td>Links to a lane without becoming the lane identity</td></tr><tr><td><code>proof.*</code></td><td>Evidence record</td><td>Links lane, source, state, platform, and observation time</td></tr><tr><td><code>AIPR-*</code></td><td>Durable AI report</td><td>Links to the execution run and authority envelope</td></tr></tbody></table>
<p>Historical <code>ticket</code> values remain readable. A value shaped like <code>AIF-NNN</code> is a
legacy lane reference; another value is an external ticket reference. Older
records that placed an <code>AIPR-*</code> report identity in <code>run_id</code> remain visible as a
compatibility seam. New records keep execution and report identities separate.</p>

<h2 id="data-flow-rule"><a class="no-underline" href="#data-flow-rule">Data-flow rule</a></h2>
<p>DotTalk++ source contracts feed HELP and metadata stores. Those stores feed
manual generation, comparison, proofs, and Portal reports. AIF claims, global R
rulings, runs, work items, and proofs pass through the identifier crosswalk
before status is projected to the website.</p>
<p>The arrows never make the website authoritative. A correction is made in the
owning engineering source or registry, validated there, and then republished.</p>
