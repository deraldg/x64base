6:T1c39,<p><strong>Status:</strong> Guided draft with a runtime-observed conceptual foundation.</p>
<p><strong>Audience:</strong> Beginning database students, self-learners, and instructors.</p>
<p><strong>Estimated time:</strong> 30 to 45 minutes after the runtime and sample data are
available.</p>
<p>This lesson teaches the difference between a table, a record, a field, table
structure, and current row state. It is the first public exemplar of the
Laboratory Campus proof-aware lesson pattern.</p>
<h2 id="evidence-boundary"><a class="no-underline" href="#evidence-boundary">Evidence Boundary</a></h2>
<p>The educational reference section was captured successfully by the registered
proof <code>proof.lab.database_literacy_starter.first_run</code>.</p>
<p>The table-backed section below is a documented, read-only extension based on
the public Quickstart and command catalog. It was not part of that original
registered first-run transcript. The lesson therefore remains a guided draft,
not <code>student_ready</code>.</p>
<h2 id="learning-objectives"><a class="no-underline" href="#learning-objectives">Learning Objectives</a></h2>
<p>By the end of the lesson, a learner should be able to:</p>
<ol>
<li>define table, record, and field in their own words;</li>
<li>distinguish table structure from the values in a particular row;</li>
<li>identify what <code>FIELDS</code>, <code>STRUCT</code>, and <code>LIST</code> reveal;</li>
<li>explain why visible runtime output is evidence that must be interpreted;</li>
<li>identify which part of the lesson is runtime-observed and which part is a
documented extension.</li>
</ol>
<h2 id="prerequisites"><a class="no-underline" href="#prerequisites">Prerequisites</a></h2>
<ul>
<li>Complete the public <a href="/docs/getting-started/installation">Installation</a> and
<a href="/docs/getting-started/quickstart">Quickstart</a>.</li>
<li>Build the sample databases before opening <code>STUDENTS</code>.</li>
<li>Use a disposable copy for any later mutation exercise. This lesson itself is
read-only.</li>
</ul>
<h2 id="part-a-establish-the-vocabulary"><a class="no-underline" href="#part-a-establish-the-vocabulary">Part A: Establish the Vocabulary</a></h2>
<p>Start DotTalk++ and run:</p>
<pre><code class="language-text">HELP /ED MODEL
HELP /ED TABLE_RECORD_FIELD
</code></pre>
<p>Record the definitions returned by the runtime. The registered first-run proof
observed the following relationships:</p>
<ul>
<li>a table is a collection of records with a defined structure;</li>
<li>a record is one row in a table;</li>
<li>a field is one named value inside a record;</li>
<li><code>STUDENTS</code> is a table, the current student is a record, and <code>SID</code>, <code>LNAME</code>,
<code>FNAME</code>, and <code>GPA</code> are example fields.</li>
</ul>
<h2 id="part-b-inspect-a-real-table"><a class="no-underline" href="#part-b-inspect-a-real-table">Part B: Inspect a Real Table</a></h2>
<p>Select the x64 sample-data lane before opening the table:</p>
<pre><code class="language-text">DO X64
USE STUDENTS
FIELDS
STRUCT
LIST NEXT 5 FNAME, LNAME, MAJOR, GPA
</code></pre>
<p>These commands are read-only in this lesson:</p>

























<table><thead><tr><th>Command</th><th>Observation target</th></tr></thead><tbody><tr><td><code>USE STUDENTS</code></td><td>Establishes <code>STUDENTS</code> as the current work area.</td></tr><tr><td><code>FIELDS</code></td><td>Lists field names, types, lengths, and decimal information for the current work area.</td></tr><tr><td><code>STRUCT</code></td><td>Reports the table structure and available index/container information.</td></tr><tr><td><code>LIST NEXT 5 ...</code></td><td>Displays values from five records using a selected field projection.</td></tr></tbody></table>
<p>If the table cannot be found, confirm that the sample databases were built and
that <code>DO X64</code> ran before <code>USE STUDENTS</code>.</p>
<h2 id="observation-worksheet"><a class="no-underline" href="#observation-worksheet">Observation Worksheet</a></h2>
<p>Complete this table from the runtime output:</p>

































<table><thead><tr><th>Question</th><th>Learner observation</th></tr></thead><tbody><tr><td>What is the current table?</td><td></td></tr><tr><td>Name four fields and record their types.</td><td></td></tr><tr><td>What does <code>STRUCT</code> reveal that <code>LIST</code> does not?</td><td></td></tr><tr><td>What does <code>LIST</code> reveal that <code>FIELDS</code> does not?</td><td></td></tr><tr><td>Which output describes the table as a whole?</td><td></td></tr><tr><td>Which output shows values from individual records?</td><td></td></tr></tbody></table>
<h2 id="assessment-questions"><a class="no-underline" href="#assessment-questions">Assessment Questions</a></h2>
<ol>
<li>Explain the difference between a table and a record without using the words
"file" or "row".</li>
<li>If every record contains a <code>GPA</code> field, does that mean every record contains
the same GPA value? Explain.</li>
<li>Why can table structure be inspected before choosing one record to discuss?</li>
<li>Which command would you cite as evidence for a field's type and length?</li>
<li>Which claims in this lesson are backed by the registered first-run proof,
and which rely on the documented table-backed extension?</li>
</ol>

<li>the filled observation worksheet;</li>

<li>the DotTalk++ build or version used;</li>
<li>the selected data lane;</li>
<li>any unexpected output or setup failure.</li>
</ul>
<h2 id="instructor-notes"><a class="no-underline" href="#instructor-notes">Instructor Notes</a></h2>
<ul>
<li>Do not treat a successful screen display as evidence of learning by itself.</li>
<li>Ask learners to cite the command output supporting each answer.</li>
<li>Preserve unexpected results rather than coaching students to erase them.</li>
<li>Keep this lesson read-only. Mutation commands belong in a separate exercise
using disposable data and explicit reset instructions.</li>
<li>Compare observations across runtime versions only when the version and data
lane were recorded.</li>
</ul>
