DotTalk++

Author
 Derald Grimwood

Dedicated to
 Kathy Grimwood

Project
 DotTalk++ is a modern C++ xBase-inspired database runtime and command shell.

Heritage
 The DotTalk++ command model draws inspiration from the classic xBase
 lineage of database languages:

 dBase - early interactive database shell
 Clipper - compiled xBase systems
 FoxPro - relational navigation and index-driven querying

 DotTalk++ preserves many of the familiar commands and workflows from
 these systems while extending them with:

 modern help catalogs
 relational traversal (REL ENUM)
 tuple projection
 scripting and automation

 DotTalk++ also combines aspects of both the interactive xBase model
 and the compiled application model. Like dBase and FoxPro, it provides
 a live command shell for exploring data. Like Clipper, it can be extended
 through source code and compiled. It is also structured as modular
 runtime libraries, including xbase and xindex, beneath the shell.

History
 The project traces back to 1993, when Derald Grimwood wrote a small
 ANSI C database program as a practical and experimental system,
 including fixed-length record storage and a simple in-memory B-tree.

 In 2025, that earlier work was revived and used as the conceptual basis
 for a modern 64-bit rebuild in C++. The result became DotTalk++:
 not a direct port, but a broader reimplementation and expansion.

Current Direction
 DotTalk++ aims to retain the clarity of the xBase interaction model
 while making the engine suitable for modern experimentation and
 education.

 It is intended to serve as:
 - a working DBF database runtime
 - a relational exploration environment
 - a scripting and automation shell
 - a teaching system for database concepts

 Internally, DotTalk++ is also organized as a modular system:
 - xbase : core DBF/table/runtime library
 - xindex : indexing library
 - dottalk : command shell and interactive environment

 In this sense, DotTalk++ sits between FoxPro and Clipper:
 - interactive and stateful like FoxPro
 - extensible and compilable like Clipper

Design Philosophy
 DotTalk++ is intentionally stateful and interactive.

 It exposes important runtime concepts directly, including:
 - current work area
 - current record pointer
 - active order/index
 - active filter
 - relation graph
 - buffering state

 The goal is to make database behavior visible and understandable during
 live operation, rather than hiding it behind abstraction.

Working Model
 DotTalk++ can be understood as four cooperating layers:

 1. Command Layer - interactive commands and scripting
 2. Data Layer - tables, records, fields, indexes
 3. Logic Layer - expressions, predicates, control flow
 4. Projection Layer - LIST, SMARTLIST, TUPLE, REL ENUM, browsers

Runtime Environment
 OS family   : Windows
 Architecture: x64
 C++ standard: C++2020
 Compiler    : MSVC 1,944

Years
 Origin: 1993 ANSI C
 Revival / C++ X64 modern rebuild: 2025-

Summary
 DotTalk++ honors the xBase tradition while extending it into a modern,
 teachable, experiment-friendly database runtime.

 User interfaces change, languages change, but the underlying database principles remain constant. -- Derald Grimwood

VDISK
  VDISK MOUNT|UNMOUNT|STATUS|CONFIG
  Activate the in-process RAM virtual disk for in-memory tables (AIF-043). MOUNT points the DBF/INDEXES/LMDB path slots under the relocatable RAM slot (default data\ram) and mounts it as an xbase::ramfs virtual root, so CREATE X64, USE, and native CDX-V64 live entirely in RAM with no files on disk. UNMOUNT drops all RAM files and unmounts (ephemeral teardown). STATUS reports the RAM root, mount state, byte usage, and resident file list. CONFIG shows the optional bin/vdisk.ini admin config (enabled/root/mode/size/warn_pct/on_full), the Layer-1 sizing recommendation, and the Layer-2 soft budget. Relocate the RAM root with SET PATH RAM <path> (or the vdisk.ini root key) before MOUNT. Typically activated via DO mem.

TABLE
  TABLE <subcommand> ...
  Table buffering / stale tracking.

        Subcommands:
            TABLE ON
                Enable table buffering for the current area. REPLACE writes into a per-field buffer and
                marks fields STALE instead of immediately writing to disk.

            TABLE OFF
                Disable buffering. REPLACE writes directly to disk (no buffering).

            TABLE STALE
                Show which fields are currently stale (buffered) for the current area.

            TABLE FRESH [ALL|<n>|<n>,<m>]
                Apply buffered updates to disk and clear stale flags on success.
                (Scope forms depend on build; ALL / area lists were previously supported.)

        Notes:
            - In current shakedown observations, LIST output reflects the physical record, not buffered overlays.
            - Some builds may not recognize TABLE REFRESH; prefer TABLE FRESH.

REL
  REL <subcommand> ...
  Relations engine commands (native DotTalk++ relation graph).

Subcommands:
    REL LIST
    REL LIST ALL
    REL REFRESH
    REL ENUM [LIMIT <n>] <child1> [<child2> ...] TUPLE <tuple-expr>
    REL SAVE [path] | REL SAVE AS <dataset>
    REL LOAD [path] | REL LOAD AS <dataset>
    REL ADD <parent> <child> ON <field>[,<field>...]
    REL CLEAR <parent>|ALL

Examples:
    REL LIST
    REL ADD STUDENTS ENROLL ON SID
    REL ADD ENROLL CLASSES ON CLS_ID
    REL REFRESH

    REL ENUM LIMIT 10 ENROLL CLASSES TASSIGN TEACHERS TUPLE ;
        STUDENTS.SID,STUDENTS.LNAME,ENROLL.CLS_ID,CLASSES.CID,TEACHERS.LNAME

Conceptual Model:
    REL maintains a directed relation graph between work areas.
    REL ADD defines edges.
    REL REFRESH recalculates relation state.
    REL ENUM traverses the graph and emits tuple rows.

Traversal Behavior:
    REL ENUM performs depth-first traversal of the relation chain.
    Each successful path produces one tuple row.

    Example chain:
        STUDENTS -> ENROLL -> CLASSES -> TASSIGN -> TEACHERS

Matching:
    Current implementation uses same-name field equality:
        parent.FIELD == child.FIELD

Notes:
    REL is the native DotTalk++ relation system.
    FoxPro-style SET RELATION commands map into this backend.

    REL ENUM is the row enumeration engine used by relational
    browsers and tuple views.

REL ENUM
  REL ENUM [LIMIT <n>] <path...> TUPLE <tuple-expr>
  Traverse a relation chain and emit tuple rows.

Syntax:
    REL ENUM [LIMIT <n>] <child1> [<child2> ...] TUPLE <tuple-expr>

Example:
    REL ENUM LIMIT 5 ENROLL CLASSES TASSIGN TEACHERS
        TUPLE STUDENTS.SID,STUDENTS.LNAME,TEACHERS.LNAME

Execution Model:
    1. Current selected area is the root.
    2. Each child token represents the next relation edge.
    3. Traversal expands matches depth-first.

Example traversal:
    STUDENTS
        -> ENROLL
            -> CLASSES
                -> TASSIGN
                    -> TEACHERS

Each complete path emits one tuple row.

LIMIT:
    LIMIT applies to emitted rows, not intermediate matches.

Projection:
    The TUPLE clause defines which fields are emitted.

Used By:
    SIMPLEBROWSER
    SMARTBROWSER
    relational tuple views.

Usage:
  DOTHELP <term>
  HELP /DOT <term>
. FoxPro-style commands (subset):
  USE          - Open a DBF in the current work area, auto-attach memo storage, and auto-attach flavor-appropriate indexes unless NOINDEX is specified.
  CLOSE        - Close the current work area or close all open tables (FoxPro: CLOSE TABLES/DATABASES/ALL).
  SELECT       - Select the active work area by number or alias.
  AREA         - Report or set the current work area slot.
  DBAREA       - Report or inspect the current DbArea/workspace (diagnostics).
  STATUS       - Display area status.
  STRUCT       - Display table structure.
  FIELDS       - Show structure (field list).
  TOP          - Go to first record.
  BOTTOM       - Go to last record.
  GOTO         - Go to record number.
  SKIP         - Move the record pointer forward/backward by <nRecords> (default 1).
  RECNO        - Return the current record number.
  INDEX        - Create an index on an expression (DotTalk++ adaptation: CDX via TAG/OF, INX via TO).
  SET          - Modern settings/index router.

        Public syntax:
            SET INDEX TO <table>.cdx
            SET ORDER TO TAG <tag> [IN <alias>]
            SET ORDER TO <tag>
            SET ORDER TO 0
            SET FILTER TO <expr>
            SET FILTER TO
            SET TALK ON|OFF
            SET ECHO ON|OFF
            SET DELETED ON|OFF
            SET CASE
            SET CASE ON|OFF
            SET UNIQUE
            SET UNIQUE FIELD <field> ON|OFF
            SET RELATION[S] <args...>
            SET PATH
            SET PATH RESET
            SET PATH <slot> <path>

        Output routing:
            SET CONSOLE ON|OFF
            SET PRINT ON|OFF
            SET PRINT TO <file>
            SET ALTERNATE ON|OFF
            SET ALTERNATE TO <file>

        Notes:
            This is the preferred public entry point.
            Older standalone forms such as SETINDEX / SETORDER / SETFILTER / SETCASE
            are compatibility or internal targets behind the routed SET command.
  SET INDEX    - Preferred public syntax for attaching the current area's CDX container.
  SET ORDER    - Preferred public syntax for activating a tag or returning to physical order.
  SETINDEX     - Compatibility/internal target behind routed SET INDEX.
  SETORDER     - Compatibility/internal target behind routed SET ORDER.
  REINDEX      - Legacy INX rebuild path. Public CDX/LMDB workflow typically uses BUILDLMDB or COMMIT-triggered rebuilds.
  CNX          - Index container command (CNX multi-tag support).
  SETCNX       - Developer/transitional command for CNX container attachment.
  SETCDX       - Developer/transitional command for direct CDX container attachment.
  SETLMDB      - Developer/transitional LMDB utility command. Public index workflow prefers SET INDEX / SET ORDER / BUILDLMDB.
  CDX          - Developer/transitional CDX command family.
  BUILDLMDB    - Rebuild CDX/LMDB tags for the current table/container.
  LMDB         - Developer LMDB utility command family for direct backend inspection/testing.
  LIST_LMDB    - Developer listing helper for LMDB-backed order inspection.
  FIND         - Find a value in the current order/index (FoxPro: FIND).
  SEEK         - Seek an exact match using the current index/order.
  INDEXSEEK    - Seek using the active index/order (DotTalk++ seek wiring).
  LIST         - List records with optional field selection and filtering (default skips DELETED unless DELETED/ALL is specified).
  DISPLAY      - Display the current record (optionally selected fields).
  COUNT        - Count matching records; optionally store the result to a variable.
  LOCATE       - Locate the first record matching a predicate/filter.
  WHERE        - Apply an SQL-like filter to the current context.
  SET FILTER   - Preferred public syntax for setting or clearing the current filter.
  SETFILTER    - Compatibility/internal target behind routed SET FILTER.
  CLEAR        - Clear current state (filters/orders/relations) depending on context.
  SET CASE     - Preferred public syntax for viewing or setting case-sensitive comparison mode.
  SETCASE      - Compatibility/internal target behind routed SET CASE.
  PREDHELP     - Help for predicates/expressions and filtering.
  PREDICATES   - List supported predicates/operators for filtering.
  SMARTLIST    - LIST-style output with SQL-grade filtering (order-aware).

        Examples:
            SMARTLIST 20 FOR gpa >= 3.5
