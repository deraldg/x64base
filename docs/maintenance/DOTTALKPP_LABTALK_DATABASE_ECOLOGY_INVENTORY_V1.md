## Purpose

This is the first curatable inventory of database-bearing artifacts under the
requested roots. It separates a logical database from its replicas, indexes,
memos, schemas, generated outputs, proofs, backups, and browser residue.

No database was opened for write, repaired, moved, or deleted. SQLite schema
reads used read-only connections. DBF and LMDB findings came from filenames,
headers, hashes, Git visibility, companions, governing scripts, and existing
lane documents.

## Curation gaps

1. No database/dataset registry existed before this inventory. The physical
   estate was discoverable only by scanning directories and old lane records.
2. Zero SQLite and zero LMDB environments are tracked. That is acceptable only
   where tracked schemas, inputs, checksums, and rebuild commands reproduce
   them. It is a durability failure where those inputs are also untracked.
3. Only 62 of 853 DBFs are tracked. Untracked does not mean orphan, but it does
   mean a clean checkout cannot be assumed to contain the observed runtime.
4. The Cascade package and mirror are the largest immediate admission gap: the
   canonical SQLite, generator inputs, 43-object mirror, and duplicate output
   need one governed source/generated/ignored policy.
5. Browser-profile databases belong outside the repository tree even when
   ignored. A temporary directory outside the workspace would reduce privacy
   and accidental-publication risk.

## Remediation installed

The first remediation pass is preventive and reversible:

1. `tools/database_ecology/database_ecology.py` now reproduces the physical
   census read-only and hard-fails when the maintained registry drifts.
2. The same tool generates and verifies a hash-bound sidecar intake candidate.
   Batch `DBECO-20260810-001` contains 239 file rows: 215 Cascade duplicates
   and 24 probe, misplaced, or generic-index files. Every row is untracked,
   marked `candidate_not_approved`, preserves its source-relative path, and
   targets `D:\code\ccode.sidecar\holding\DBECO-20260810-001`. Zero files were
   moved.
3. `tools/cascade_erp/run_dual_schema_mirror.ps1` now calls the scanner's
   Cascade preflight before it creates or imports anything. The runner refuses
   to proceed while legacy root output remains, preventing another ambiguous
   mirror proof.
4. The sidecar plan verifier recomputes every source size and SHA-256, rejects
   duplicate or escaping paths, checks Git tracking state, requires the
   review-gated state, and refuses destinations that already exist.

The first dry run caught a Windows-specific safety defect: case-insensitive
`CASCADE_*` matching also selected the canonical `cascade_erp` directory. The
tool now treats glob matches as files only, and a regression protects the
canonical directory from sidecar intake.

## Public localhost schema surface

The localhost x64base website now exposes a dedicated `/schemas/` page in its
top navigation. Schema presentation is deliberately absent from the homepage.
The page names all 34 Cascade tables and 9 analytical views and displays two
Mermaid-derived, provenance-checked SVGs: a seven-module relational map and the
SQLite-authority-to-x64base-mirror carrier contract. A third catalog SVG and a
separate "Other database schemas" section cover MCC x64/x32/VFP/original,
Bible and Pinocchio reference data, HELP, runtime metadata, identity/RBAC,
AI-BBS, AI Portal tracking, data dictionary, source comments, manual assembly,
messaging, locale, PyCRUD, memo/dialect fixtures, and sandbox/probe families.
LMDB, CDX, and CNX are identified as derived indexes rather than invented as
separate table schemas. This is a public-facing local view, not a hidden portal
item and not a claim of Internet publication.

The homepage keeps `LMS` as the label but describes the current boundary
honestly: LabTalk does not enroll or grade students and is not a complete LMS.
Its teaching units may be used as modules, reduced to agent skills, packaged as
plugins, or connected later through the reserved provider-neutral boundary.
Architecture is no longer a top-level hero/navigation claim; it appears below
the LMS boundary as supporting material.
