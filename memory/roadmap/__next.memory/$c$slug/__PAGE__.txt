2:Td12,<h2 id="why-an-optimization-project"><a class="no-underline" href="#why-an-optimization-project">Why an optimization project</a></h2>
<p>The quality of the whole memory system reduces to the quality of one decision, repeated: which
short-term memories become permanent. A perfect store with a poor value function is a warehouse of
trivia; a modest store with a good one is a memory. So the triage program is framed as an
optimization project -- tuning the value function, and the pipeline around it, is the work. It is
chartered as a development lane in the AI Frontal Memory project, with a running core already in
place and a phased runway ahead.</p>

<h2 id="the-core-is-real"><a class="no-underline" href="#the-core-is-real">The core is real</a></h2>
<p>M0 is not a plan. The value function runs as <code>tools/memory/consolidate.py</code>: it scores a session's
working set, buckets each candidate as promote, hold, or discard against a threshold tuned to the
domain's cost asymmetry, and emits a hybrid proposal. A companion renderer turns an
owner-confirmed proposal into attributed post records ready for the durable write. Its acceptance
test is a closed loop: the tool reproduces, on this project's own session, the same keep-and-drop
decisions a person made by hand.</p>
<h2 id="the-discipline-that-keeps-it-honest"><a class="no-underline" href="#the-discipline-that-keeps-it-honest">The discipline that keeps it honest</a></h2>
<p>Two rules govern the whole lane. <strong>Measure, do not assert:</strong> the claim that retention cuts
time-to-context and mistake rate is instrumented before it is believed. And <strong>no wheel
reinvention:</strong> the program consumes the parts the platform already has -- the durable store, the
locking, the attributed write path, the recall graph -- and a named, verified gap is the only
license for building something new. Forgetting remains the point: the end state is not total
